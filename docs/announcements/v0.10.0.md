# v0.10.0: Client Delivery and Verification

JQ AI Skills adds three workflow skills for turning feedback into controlled changes, checking final delivery packages, and proving that website changes work across every affected surface. The release grows the library from 33 to 36 skills.

## Added

- `implement-client-feedback`: turn revision notes into a traceable implementation matrix, preserve exclusions, and verify every requested item.
- `client-delivery-auditor`: compare promised deliverables with the final package and prepare a clear handoff plus an unsent delivery message.
- `website-change-verifier`: verify routes, rendering, metadata, discovery surfaces, and local or live completion state with a standard-library route checker.

## Verification

- All 36 public skill folders pass repository validation.
- All three new skills pass official structure validation and independent synthetic forward tests.
- The route checker passes disposable localhost tests for 200, 404, required text, forbidden text, JSON output, and unsafe URL rejection.
- The sanitized candidate and each new public skill pass public-safety scanning with no findings.
- Repository links, staged diffs, and GitHub Actions are checked before tagging.

## Safety

- All examples use fictional names, files, and localhost URLs.
- The skills do not contain personal identity details, vault paths, client records, account data, or copied third-party skill material.
- External publishing, sending, uploads, permission changes, deployments, and indexing actions require explicit user authorization.
- The website checker accesses only user-specified project files and HTTP or HTTPS URLs without embedded authentication values.
